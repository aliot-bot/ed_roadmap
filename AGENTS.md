# Инструкции для работы с проектом

Тебя зовут Маки.

## Назначение

«Карта знаний» — персональное self-hosted приложение для дорожных карт. Не добавляй функции за пределами текущих контрактов, архитектуры и явного запроса пользователя.

## Границы и устройство

- `backend/` — Go-монолит: domain, service, repository, HTTP и MCP-адаптеры, миграции.
- `frontend/` — React/TypeScript SPA, graph/tree-интерфейс и тесты компонентов.
- `docs/` — архитектура, API, БД, решения, развёртывание и аудит безопасности.
- `scripts/`, `compose.yaml`, `Caddyfile`, `.env.example` — эксплуатация и инфраструктура.

REST и MCP используют общий service-слой. PostgreSQL — единственный источник истины. Иерархия тем и prerequisite-связи — разные сущности. Прогресс считается только по листовым темам и меняется только пользователем; MCP не должен менять прогресс или заметки.

## Правила изменений

1. Перед изменением прочитай относящиеся к нему требования, контракт API и существующие тесты.
2. Сохраняй ownership: один идентификатор не даёт доступа без проверки владельца. Проверяй границы владельца и roadmap в каждом пути данных.
3. Бизнес-правила, валидацию циклов, лимиты и транзакционные инварианты держи в domain/service, не дублируй их в HTTP, MCP или UI.
4. Для изменений схемы добавляй новую forward-миграцию; не редактируй уже применённые миграции. SQL должен быть параметризованным.
5. Для browser-мутаций сохраняй session/CSRF-защиту. Для MCP сохраняй bearer-аутентификацию, узкие scopes, лимиты пакетов и идемпотентность записей.
6. Не логируй секреты, cookie, bearer-токены, полные тексты заметок или необработанные ошибки БД.
7. Не публикуй сервис, не меняй DNS, не вращай реальные секреты и не перезаписывай рабочую БД без явного разрешения.

## Качество и проверка

- Backend: форматирование, релевантные `go test ./...`, а при изменении конкурентности или хранилища — проверка PostgreSQL-пути на чистой БД.
- Frontend: `npm run lint`, `npm test`, `npm run build`; после заметных UI-изменений проверь реальные состояния на 320, 390, 768, 1024 и 1440 px, клавиатуру и отсутствие горизонтального скролла.
- Infrastructure: проверяй `docker compose config --quiet`; backup всегда восстанавливай сначала в отдельную БД.
- Документацию и OpenAPI обновляй одновременно с изменением публичного поведения.

## Завершение работы

Сообщай только о фактически выполненных проверках, перечисляй ограничения и не называй релиз готовым при непроверенных обязательных сценариях. Держи изменения небольшими и не затрагивай несвязанные файлы.
